Architecture and runtime map

OBSERVED source inventory with DECIDED boundaries and explicitly labeled open gates

A source-adjacent map of the Go search/index backend: public contract, service coordination, exact catalogue, durable generations, bounded live traversal, observation, candidate similarity, transport, and verification.

Non-negotiable boundaries

  • The filesystem is authoritative; catalogue and index state are projections.
  • Public engine operations never mutate source files.
  • Exact identity and stored records remain authoritative over candidate channels.
  • JSONL is the development and conformance projection; the M4 dogfood service uses authenticated bounded local framing.
  • Semantic interpretation and personal memory remain Orchestrator-managed concerns outside this engine.
  • A damaged or absent engine may reduce search capability but must not disable navigation.

Runtime flows

Checked catalogue query

  1. JSONL request is decoded under the one-frame ceiling.
  2. Service admits a lifecycle-counted query operation.
  3. Approved-root snapshot and checked reader generation are pinned.
  4. Exact planner applies scope, filters, order, candidate, and cursor bounds.
  5. Ranking maps exact matches to evidence-bearing API results.
  6. Response names generation, plan, cursor, staleness, and warnings.

Authoritative reconcile and publication

  1. Administrative operation serializes behind the service admin lock.
  2. Scanner traverses one approved root through the sandbox or manifest-bound capability.
  3. Most-specific root ownership prunes independently approved child roots.
  4. Unchanged durable state returns without a publication write.
  5. Changed state publishes and validates a new immutable generation.
  6. Reader swap retains old-generation safety and then preserves rejected recovery evidence.

Zero-catalogue live query

  1. Service verifies the root is already approved and still resolves inside the sandbox.
  2. Live manager creates or resumes one bounded, expiring scan session.
  3. Traversal keeps bounded depth/open directories and never follows directory links.
  4. Matched paths receive exact platform observations at read time.
  5. Page returns discovery order, work counters, explicit unavailable paths, and no catalogue generation.

Shutdown

  1. Lifecycle changes from ready to draining and rejects new work.
  2. Service lifetime cancellation reaches admitted operations and background observation.
  3. Shutdown waits for the bounded active-operation count to drain.
  4. Live cursors and the current exact reader are closed.
  5. State becomes stopped or faulted without writing a clean-stop marker.
