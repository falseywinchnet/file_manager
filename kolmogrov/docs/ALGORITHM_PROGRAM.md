# Algorithm program: oracle to ultimate hash

Status: **candidate construction ladder**.

## Phase A — perfect breakdown

Build an audit-first reference encoder that emits canonical sparse features,
not a compact vector. Every emitted feature records:

- channel and subfamily;
- exact source span/node/edge;
- resolution and direction;
- count/magnitude;
- prevalence scope and generation;
- normalization contribution;
- transformation lineage in synthetic fixtures.

Start with raw bytes and Unicode sequences before tokenization. Add token,
filename/path, code, and OCR views without deleting lower-level evidence.

The reference distance report decomposes every score into channel, feature
intersection, unmatched mass, positional movement, containment, and shape. It
must explain why two objects are close and why a hard negative is separated.

### Phase A support-scale gate

Before fixed width, test the candidate semantic-cylinder tower in
`SUPPORT_SCALE_JACOBIAN_PROGRAM.md` and `ALGORITHMIC_SUPPORT_BASIS.md`:

- canonical witness atoms receive nested, axis-declared routes;
- parent state must be a contraction of child state or expose its exact
  projective residual;
- coarse/detail energy, thresholded Jacobian support, atomic SNR, and relevant
  conditional information remain separate reports;
- sign-only fine hashes may not be used to derive coarse signs without the
  margin support required by T-QUANT-SCALE-1;
- scale stops only at a declared loss/SNR gate, never because a chosen width is
  aesthetically convenient.

This gate admits a construction for falsification. It does not select the
semantic route, base, norm, or quantizer.

## Phase B — channel candidates

Evaluate independently:

### Content

- byte/character/token 1–n grams;
- multiset counts and bounded log counts;
- word-shape and script features;
- rare fragment/motif dictionaries;
- exact literal side channel.

### Position

- soft bins at dyadic and adaptive resolutions;
- orthogonal moments and wavelet-like bases;
- rank/quantile coordinates;
- boundary, center, and hierarchical positions;
- content-position crosses.

### Combination

- contiguous paths;
- skip paths and bounded gaps;
- global ordered subsequences;
- dependency/typed relation paths where evidence exists;
- cross-resolution and cross-channel interactions;
- repetition and symmetry signatures.

### Shape and magnitude

- raw and logarithmic length;
- unique ratio, entropy controls, density, run structure;
- hierarchy depth/branching;
- modality-specific bounded measures.

### Directional relations

- containment;
- crop/subsequence evidence;
- source-to-query and query-to-source asymmetry;
- ambiguity-class output.

Every family faces a sparse exact baseline and channel ablation before hashing.

## Phase C — prevalence

Compare global, per-root, per-type, per-channel, and multi-scale prevalence.
Candidate transforms include smoothed inverse frequency, bounded log odds,
information gain, and description-cost weights. Reject any transform that:

- allows a common family to erase rare exact evidence;
- changes drastically after a small corpus update;
- enables cheap adversarial flooding;
- leaks private cross-root statistics;
- makes hashes incomparable without exposing generation identity.

## Phase D — fixed-width families

Compare equal serialized budgets, initially:

- 64, 128, 256, 512, 1024, 2048 bits for compact binary signatures;
- 102, 198, 390, and 774 scalar dimensions for continuity with ConeDAG studies;
- multiple independent addresses whose total bits equal the fused baseline;
- full-precision, 16-bit, 8-bit, ternary, sign, and learned/nonlearned
  quantization as separate candidates.

Candidate organizations:

- concatenated normalized channel vector control;
- independent per-channel hashes;
- independent per-resolution hashes;
- shared content anchor plus specialized address satellites;
- error-correcting or redundant channel layouts;
- adaptive bit allocation frozen by object class, never per-query magic.

The hash configuration includes every seed, feature version, prevalence
generation, normalization, weight, quantizer, width, and byte order.

## Phase E — indexing and top-k

Flat exact scan is the correctness baseline. Compare only after it misses a
declared latency gate:

- multi-probe LSH or bucket families;
- Hamming/radius indexes for binary signatures;
- coarse channel routing plus exact rerank;
- graph/ANN candidates only under deterministic-build, deletion, memory, and
  recall gates;
- PRV-derived or reciprocal-rank fusion over channel top-k lists.

No index may hide a candidate that the hash theorem says must be returned under
its assumptions. Every approximate index exposes its miss rate separately from
hash-quality error.

## Phase F — optimization

Freeze reference outputs first. Then investigate:

- streaming feature enumeration;
- bounded bottom-k/priority sampling without materializing feature sets;
- cache-aware contiguous storage;
- preallocated workspaces and zero hot-path allocation;
- parallel channel construction with deterministic reduction;
- vectorized hashing, quantization, and distance;
- batched query/candidate kernels;
- CPU feature dispatch and portable scalar fallback;
- GPU only for workloads that measure a net system win.

An optimized path must either produce bit-identical hashes or have a proof and
differential tolerance defining equivalence. Speed results include end-to-end
candidate verification, not only dot-product throughput.

## Ultimate release object

A release contains:

- normative mathematical specification;
- canonical reference implementation;
- optimized portable library and stable C ABI;
- fixed conformance vectors;
- corpus/experiment manifests;
- theorem and negative-results ledger;
- deterministic configuration IDs;
- migration and cross-version comparison policy;
- File Manager engine adapter kept outside this project.
