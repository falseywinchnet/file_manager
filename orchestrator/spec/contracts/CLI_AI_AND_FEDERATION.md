# ORC-CLI / future plugin-AI / ORC-FED contracts

Status: **CLI Core bootstrap stable at 1.0; plugin AI stubbed; federation deferred**.

## Local CLI

The initial Orchestrator API is the local CLI. Human-readable output is the
default; `--json` and `serve-stdio` project the same bootstrap operations into
structured responses.

A human, local AI tool, or developer agent invoking the CLI has the same local
user authority. Orchestrator does not inspect whether text was typed by a human
or generated by a local agent. This equality does not grant file mutation,
plugin, semantic-fact, engine-administration, or content-read powers that the
operation itself lacks.

The implemented bootstrap methods are:

- `orchestrator.version`;
- `orchestrator.release`;
- `orchestrator.status`;
- `orchestrator.frontend.bootstrap`;
- `orchestrator.contracts.list`;
- `orchestrator.availability.list`;
- `orchestrator.shutdown`;
- status-only plugin and semantic-fact stubs.

## Plugin AI

“AI API” in the future plugin system means an application/plugin capability
surface that may access search, File Manager functionality, and other explicitly
granted operations as an app. It does not describe agents developing this
repository or ordinary local developer agents using the CLI.

No plugin-AI operation schema exists in the bootstrap. It is reported as part
of the stubbed plugin system and will be designed alongside the plugin API.

## Semantic facts

No semantic-fact create, propose, commit, query, or erase API is admitted yet.
Only `orchestrator.semantic_facts.status` exists and reports `stubbed`. The
architect's semantic-engine design will define the future authority model.

## Federation

Remote/network work is not core ambient discovery. Future federation must
preserve original channel evidence, availability, deadlines, partial failure,
and exact object anchors. Full indexes remain at their sources; local coarse
catalogues require explicit policy. No federation operation exists today.
